# 业务规则

## 使用者

医保理赔审核员使用本工作台处理重叠消重与支付方顺序。

## 主规则

同一成员同一服务日按支付方优先级依次给付，合计不得超过最高票据金额。

计算以整数最小单位或十进制定点数为准，避免二进制浮点在边界上漂移。无法完成前置校验的行进入隔离区；跨行规则在计算后标记阻断或人工复核。

## 判定

- `PASS`：业务结果在允许范围内。
- `REVIEW`：数据可计算，但需要人工确认或存在轻微偏离。
- `REJECT`：存在来源、守恒、方向或上限阻断，不能签发。

## 批次

同一来源重复执行得到同一批次数值。签发要求阻断项为零，并携带当前版本号；旧版本提交会被拒绝。证据只在签发后生成。

## 顺位结算与追回补付

同一成员同一服务日构成一个结算组，支付方优先级为 `MEDICARE < PRIVATE < SELF`（顺位依次降低），金额一律以整数分记账。

1. **晚到重算**：低顺位款已签发后，晚到的高顺位理赔仍要按优先级重算各方应付；高顺位先占额度，低顺位应付被相应压缩。
2. **净实付上限**：旧款追回确认之前，全组净实付（实付减已追回）不得超过票据上限（组内最高票据金额）。
3. **当天部分付款**：票据仍有余额但不足以付清高顺位整笔时，能付的余额当天即付给高顺位，不足部分计入待补，不得留到追回后一次性付。
4. **追回后补付**：追回确认释放票据额度，系统按顺位自动补齐各方待补应付。
5. **确认幂等**：每笔追回确认带 `confirmation_key`；同一笔确认重试不重复记账、不重复补付，接口返回幂等命中标记。
6. **工作台核对**：台账逐笔展示应付、已付、已追回、净实付、待补、待追回，并校验净实付是否在票据上限内。
